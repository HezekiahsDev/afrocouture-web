# Internationalization (i18n)

The web client supports English (`en`), Hausa (`ha`), Yoruba (`yo`) and Igbo
(`ig`). The plumbing is built so more can be added without touching routing.

## How it works

- **Language lives in a cookie** (`NEXT_LOCALE`, one year), not in the URL, so
  every existing route keeps working unchanged.
- `src/i18n/config.ts` lists the supported locales and their display metadata.
- `src/i18n/dictionaries/en.ts` is the source of truth. Every key is typed; a
  missing key in another language fails `tsc`.
- `ha.ts`, `yo.ts` and `ig.ts` in the same folder hold the Hausa, Yoruba and
  Igbo copy.
- `src/i18n/I18nProvider.tsx` is mounted in the root layout. Client components
  read the active dictionary with `useI18n()`.
- `src/components/layout/LanguageSwitcher.tsx` writes the cookie and re-renders
  the tree. It sits in the navbar (desktop actions and the mobile menu).

```tsx
"use client";
import { useI18n } from "@/i18n/I18nProvider";

export function Example() {
  const { t } = useI18n();
  return <button>{t.nav.startDesign}</button>;
}
```

Interpolated and plural copy is a function in the dictionary, so both languages
keep the same signature:

```ts
// en.ts
ordersAttention: (count: number) => `Orders, ${count} need your attention`;
// ha.ts
ordersAttention: (count: number) => `Oda, ${count} na buƙatar kulawar ku`;
```

## Adding a string

1. Add the key and English copy to `src/i18n/dictionaries/en.ts`.
2. Add the Hausa, Yoruba and Igbo copy to `ha.ts`, `yo.ts` and `ig.ts`
   (TypeScript will flag each one until you do).
3. Use `const { t } = useI18n()` in the component and reference the key.

Keep brand names (`IPILE`, `AI Studio` in URLs), user-generated content, and
catalogue data (fabric names, cities, categories) untranslated.

## Adding a language

1. Add the code to `LOCALES` and `LOCALE_META` in `src/i18n/config.ts`.
2. Copy `en.ts` to the new locale file and translate it.
3. Register it in `src/i18n/dictionaries/index.ts`.

The language picker and cookie handling pick it up automatically.

## Server components

Server components can call `getDictionary(locale)` from
`src/i18n/dictionaries`. With Cache Components, reading the cookie on the server
must happen inside a `<Suspense>` boundary; do that only where localized server
HTML is genuinely needed. The current setup keeps the root layout static and
translates in client components, which covers the whole customer storefront.

## Fonts

Both fonts load the `latin-ext` subset (Hausa `ɓ`, `ɗ`, `ƙ`; Yoruba `ṣ`) and
the `vietnamese` subset (the dotted vowels `ẹ`, `ọ`, `ị`, `ụ` and the combining
tone marks Yoruba uses). A new language with other characters may need another
subset.

## Before launch

The Hausa, Yoruba and Igbo copy are working drafts. Have a native speaker of
each review product, checkout, and legal copy. In particular, confirm:

- the form of address: respectful plural "ku" (Hausa) and "ẹ"/"yín" (Yoruba),
  and "gị" (Igbo);
- Yoruba tone marks, which are written in full;
- the translations of garment, measurement and role terms (artisan, merchant,
  order).
